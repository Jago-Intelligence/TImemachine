# Incident schema v1

`@timemachine/core` defines the language-neutral incident wire contract. It has
no Node.js, framework, storage, logger or AI imports. Zod is its only runtime
dependency; `TextEncoder` is a standard web API available in supported Node.js
runtimes and browsers. The production build excludes Node.js ambient types. ESLint restricts core
source imports to Zod and local modules.

## Envelope

| Field           | Meaning                                                              |
| --------------- | -------------------------------------------------------------------- |
| `schemaVersion` | Integer `1`; never coerced from a string                             |
| `id`            | Incident UUID, generated by the producer                             |
| `occurredAt`    | Failure occurrence as a UTC ISO timestamp with milliseconds          |
| `capturedAt`    | Capture timestamp, no earlier than occurrence                        |
| `service`       | Name, deployed version and environment                               |
| `runtime`       | Language, runtime name and runtime version                           |
| `adapter`       | Producer name, version and declared capabilities                     |
| `correlation`   | Request and correlation identifiers                                  |
| `failure`       | Source, name, optional code, sanitized summary and structured frames |
| `timeline`      | Ordered, bounded typed events                                        |
| `replay`        | Unsupported reason or provisional replay candidate                   |

Language and runtime names are identifiers rather than a Node.js-only enumeration.
This permits future adapters without changing the envelope. The Python fixture is
a contract example, not an implemented Python SDK.

## Timeline and capture capabilities

All events have a unique `id` and integer `offsetMs`, relative to the start of
the captured execution. Offsets must be nondecreasing; equal offsets preserve
producer order. Wall-clock timestamps describe the incident, while relative
offsets order its events. Clock and duration controls belong to future adapters.

| Event type      | Fields beyond ID and offset                            | Required capability   |
| --------------- | ------------------------------------------------------ | --------------------- |
| `http.request`  | HTTP method and sanitized route template               | `http-metadata`       |
| `http.response` | Status code from 100 to 599                            | `http-metadata`       |
| `error`         | Reviewed error code                                    | `errors`              |
| `dependency`    | Logical dependency ID, operation ID, outcome, duration | `dependency-metadata` |

Every incident requires the `errors` capture capability because it includes a
failure summary. Capability declarations cannot contain duplicates. A dependency
ID denotes a logical dependency or fixture; it is never a connection URL, SQL
statement or credential. HTTP routes are templates such as `/orders/:orderId`,
not actual URLs or user identifiers. There are no raw headers, bodies, query
strings, arbitrary event payloads or raw stack strings in v1.

Failure frames contain project-relative file names, positive line numbers and
optional function names and columns. Absolute paths, empty or dot path segments, parent traversal, Windows
paths and URL source locations are rejected. Adapters must omit unavailable or
unsafe frames instead of transmitting raw stacks.

## Replay eligibility

An unsupported incident has one explicit reason:

- `adapter-unsupported`
- `missing-fixtures`
- `uncontrolled-nondeterminism`
- `external-side-effects`
- `capture-incomplete`

A candidate contains `mode: "node-http-fixtures-v1"` and a `fixtureSetId`. It must
come from a JavaScript or TypeScript Node.js runtime, declare that replay mode,
contain an HTTP request event and describe an HTTP handler failure.

Candidate means the metadata permits a later replay assessment. It does not
assert that fixtures exist, dependencies are mocked, determinism is controlled,
or execution is safe. The future replay engine must verify these conditions and
sandbox isolation before running anything. The fixture reference is an opaque
identifier, never a file path or remote URL. Fixture contents and a replay runner
are outside this milestone.

## Validation and limits

Use `parseIncidentJson` at the collector boundary. It validates UTF-8 wire size
before parsing JSON, then validates the schema and aggregate serialized size.
`parseIncident` accepts JSON-compatible object input, clones validated data, and
checks aggregate size. Do not pass untrusted JavaScript objects with getters or
proxies; network inputs should always go through JSON parsing.

| Limit                                  | v1 value                                                    |
| -------------------------------------- | ----------------------------------------------------------- |
| Wire and normalized envelope size      | 256 KiB                                                     |
| Timeline count                         | 1–1,000 events                                              |
| Event offsets and dependency durations | 0–86,400,000 ms                                             |
| Identifiers                            | 1–128 characters; ASCII letters, digits, `.`, `_`, `:`, `-` |
| Labels                                 | 1–128 characters after trimming                             |
| Failure summary                        | 1–2,048 characters after trimming                           |
| Stack frames                           | At most 50                                                  |
| Route template and relative frame file | At most 256 characters                                      |

Identifiers start with a letter or digit. String character limits use JavaScript
UTF-16 length; the envelope limit uses actual UTF-8 bytes. Schema primitives
and `incidentSchema` are exported for composition, but only the parser functions
enforce aggregate byte limits. Services must also limit request bytes before
buffering the request; this package cannot enforce transport buffering limits.

`IncidentValidationError` exposes a stable code and an immutable list of known
field paths (`$` denotes the root). It does not include submitted values, arbitrary unknown field names
or Zod diagnostics. The collector will map these codes to versioned API errors:

- `INVALID_JSON`
- `INCIDENT_TOO_LARGE`
- `UNSUPPORTED_SCHEMA_VERSION`
- `INVALID_INCIDENT`

Do not return or log original input when handling validation failures.

## Sanitization boundary

Structural validation cannot prove that summaries, names or otherwise valid
strings contain no secrets. Producers must sanitize before transport, and the
collector must apply its own sanitization policy before persistence. This package
does not implement automatic redaction or establish a trusted sanitization flag.
The checked-in fixtures are synthetic, without real credentials or personal data.

## Compatibility

Version 1 uses strict objects at every boundary. Unknown fields and event types
are rejected, including additive fields. Keep its wire shape and validation
semantics stable once released; new fields, events, capability names or changed
limits require a new integer schema version and explicit compatibility handling.
The package version and `/v1` API version are separate from `schemaVersion`.
Older readers reject newer schema versions rather than losing information.

Future collectors should negotiate supported versions and retain original
sanitized incidents separately from derived analysis and replay results. No
migration, permissive fallback or support for schema version 2 exists yet.

## Fixtures and verification

`packages/core/test/fixtures/node-http-candidate.json` illustrates a synthetic
HTTP failure. `python-unsupported.json` demonstrates a language-neutral incident
without replay support. Test coverage includes valid fixtures, malformed inputs,
strict field rejection, chronology, IDs, capabilities, replay restrictions,
UTF-8 limits and value-free validation errors.
