The workflow

  1. The request. A client sends POST /api/convert with amount 100 to an Express backend.
  2. The failure. The pricing service returns rate 0.9 and currency EUR. The application reads a different field and throws a TypeError, returning HTTP 500.
  3. The evidence. Follow the captured request into its approved input, dependency response and source location.
  4. The correction. Source evidence reveals the wrong field access. The developer changes pricing.ratePerUnit.toFixed(2) to pricing.rate.toFixed(2).
  5. The replay comparison. The original captured build reproduces HTTP 500 with controlled dependencies in isolation. The changed build returns HTTP 200 and a converted amount of 90 EUR; its business assertions pass.
  6. The whole story. The connected flow: capture, reproduce and verify. Historical builds, team access and alerts support continued investigation.
